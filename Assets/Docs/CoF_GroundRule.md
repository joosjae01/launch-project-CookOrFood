## 소통 

### 1. SLACK 과 DISCORD의 분리

#### 1) SLACK

- 기본적인 소통 수단으로 사용한다
- 임시적인 문서만을 관리한다
- 외부자료, 레퍼런스를 공유한다

#### 2) DISCORD

- 통화, 화면 공유를 위해 사용한다

<br>

### 2. 메시지 규칙

- 메시지를 확인했을 때에는 ✅ 이모지를 사용하여 확인한 상태임을 알린다
- `@이름` 으로 언급한 질문에 대해서는 스레드를 사용하여 답변한다
- `@here` 는 긴급 상황에서만 사용한다

<br>
 
### 3. 상호 존중

- `@이름` 으로 프로젝트에 관련하여 언급할 때에는 코어타임을 확인한다
- 코어타임에는 15분 이내에 확인 표시를 남길 수 있도록 한다

<br>

## 코딩 컨벤션

> 서로의 코드를 읽어야 하므로, 읽는 사람이 **이름만 보고 역할을 알 수 있는 것**이 목표입니다.

<br>

###  1. 이름

| 대상 | 표기 | 예시 |
|---|---|---|
| 클래스 | PascalCase | `MonsterVision` |
| 메서드 | PascalCase | `DetectPlayer()` |
| public 필드·프로퍼티 | PascalCase | `public int Hp` |
| private 필드 | underScore + camelCase | `private float _moveSpeed` |
| 지역 변수·매개변수 | camelCase | `float distance` |
| 상수 | UPPER_SNAKE_CASE | `private const float MAX_HP = 100f` |
| 인터페이스 | `I인터페이스명` | `IDamageable.cs` |
| 추상클래스 | `추상클래스명Base` | `MonsterBase.cs` |

- **줄임말을 만들지 않습니다.** `mv`, `plyCtrl` 같은 이름은 본인만 압니다.
- bool은 `is`, `has`, `can` 으로 시작하면 읽기 좋습니다. `isDead`, `hasKey`, `canMove`

<br>

### 2. 클래스 내부 순서
1. 상수
2. `[SerializeField]` 필드
3. private 필드
4. public 필드
5. 프로퍼티
6. 이벤트
7. 유니티 라이프사이클 메서드 (`Awake` → `OnEnable` → `Start` → `Update` → `OnDisable` → `OnDestroy`)
8. public 메서드
9. private 메서드

<br>

## PR 가이드
1. 미리 정해진 PR 양식에 맞춰 내용을 작성합니다.
2. PR의 담당자는 팀원 모두에게 할당합니다.
3. 절대 본인이 PR 승인하지 않습니다.
4. 머지 후 브랜치를 삭제하도록 합니다.
5. 머지 제목은 병합하는 브랜치명을 기준으로 <br>
    `feature <병합되는 브랜치 명> << <병합하는 브랜치 명>` 으로 맞춰주세요. <br>
    예시 : `feature Main << shnoh_Observable_Property`

<br>
